## ٣. الأعطال — بالموضع والعَرَض

### 🔴 ١. ما يراه المستخدم يخالف ما في القاعدة

| الحالة | الـAPI يقول | القاعدة تقول |
|---|---|---|
| فاتورة كاملة | `flagged` · `high` · `70.59` | `risk=50.00/high` · `blocks=True` |
| **ناقصة الحقول** | **`validated`** · **`medium`** · `67.65` | **`risk=50.00/high`** · **`blocks=True`** |
| مكرّرة | `flagged` · `high` · `67.65` | `risk=50.00/high` · `blocks=True` |

**الحالة الثانية تُعرَض «مُعتمَدة · متوسطة» وهي محجوبة عالية في القاعدة.**

و`blocks_approval` — الحقل الذي يمنع الاعتماد — **ليس في حمولة الاستجابة
أصلًا**. مفاتيحها: `filename` · `findings_summary` · `fraud_score` ·
`invoice_id` · `is_duplicate` · `processing_ms` · `risk_level` ·
`rules_failed` · `status` · `success` · `validation_score`.

**يمنع ٦ب؟ لا** — عطل عرض/قراءة مستقلّ عن أي مستدعٍ من الأربعة.

### 🔴 ٢. الاستخراج يكتب أرقامًا خاطئة في جدول الفواتير

الثلاث حُفظت بـ:

```
invoice_number = 'oice'      ← والملف يحمل INV-TRACE-1
total_amount   = 0.00        ← والملف يحمل 1150.00
vat_amount     = 0.00        ← والملف يحمل 150.00
```

`'oice'` بقيّة كلمة `invoice` — أثر تقطيع في تحويل CSV. والملف رُفع باسم
`complete.csv` وعُولج باسم `complete_row2.json`: الـCSV يُقسَّم صفًّا صفًّا
ويُحوَّل إلى JSON قبل الاستخراج.

⇒ **فاتورة تُحفَظ بمبلغ صفر ورقم مشوَّه، وتُدقَّق بعشرين قاعدة على هذا
الأساس.** وكشف التكرار يعمل على `'oice'` فيطابق كل فاتورة بأخرى.

**يمنع ٦ب؟ لا** — لكنه يُبطل أي قياس تكافؤ يقارن نتائج قواعد على هذا المسار.

### 🔴 ٣. مسار الفواتير لا يمرّ بـ`run_audit_compat` — مُثبَتًا بالتشغيل

```
INFO rule_engine AuditPipeline starting: document_id=… type=sales_invoice
AuditRun … engine_version = 2.0
```

و`AUDIT_ENGINE_VERSION = "v2"`، والأنبوب الذي عمل هو **V1**. المفتاح الذي
يقول `compat.py` إن تبديله «يحتاج تغيير إعداد فقط» **لا أثر له على هذا
المسار**.

⇒ الانحراف 52 مُثبَتًا بالتشغيل لا بالقراءة.

**يمنع ٦ب؟ نعم — هذا هو ٦ب بعينه.**

### 🔴 ٤. بوّابة الحصّة لم تُبلَغ

صفر ذكر لها في سجلّ ثلاث عمليات رفع كاملة. وهي تُرقّع `run_audit_compat`،
والمسار ينادي V1 مباشرةً.

⇒ **رفع فاتورة لا يستهلك حصّة ولا يُرفَض بانتهاء الاشتراك.** أثر تجاري.

**يمنع ٦ب؟ نعم — يزول بتحويل المستدعين.**

### ⚠️ ٥. ثلاثة نداءات OpenAI فاشلة في كل عملية رفع

```
ERROR finai OpenAI invoice extraction failed: 401 invalid_api_key
ERROR finai [OpenAI] Authentication failed: 401 invalid_api_key
ERROR finai AI risk analysis failed:        401 invalid_api_key
WARNING finai [AIExtractor] Tier 3 (parser fallback)
```

كلها مُبتلَعة، والمعالجة تمضي. **الرفع الواحد يستغرق 5–7 ثوانٍ**، جزء
منها انتظار ثلاثة نداءات مرفوضة.

**يمنع ٦ب؟ لا** — بيئة، والمفتاح غير صالح على هذا الجهاز.

### ⚠️ ٦. مسار الفواتير لا يُنشئ `Document`

`Document +0` · `ExtractedData 0→0` · `DocumentAnalysisResult 0→0`.
فالمساران لا يتقاسمان تخزينًا، و`core.document_resolution` لا يبلغ الفواتير.

**يمنع ٦ب؟ لا** — لكنه يفسّر لماذا `sales_invoice` وحده بلا نموذج على
`Document` في خريطة الحلّ.

## ٥. ما لم أستطع قياسه

* **التزامن الحقيقي** — لا Redis ولا عامل. كل ما بعد `.delay()` قِيس
  متزامنًا، فترتيب المهام وفشلها الجزئي وإعادة محاولاتها غير مقيسة.
* **مسار PDF/OCR** — رفعتُ CSV. سلوك OCR ومستخرِج الصور غير مقيس.
* **الرفع المتعدّد والدفعات الكبيرة** — ملف واحد لكل عملية.
* **ما يعرضه المتصفّح فعلًا** — قِست حمولة الـAPI لا الصفحة.
