القياس لم يكتمل، **لكن الشيفرة أجابت — والجواب أخطر مما كنا نقيس.**

### الأساس (`RiskEngine` — يشترك فيه الأنبوبان)

**لا مسار في الأساس يحجب اعتمادًا بسبب درجة.** الحجب دائمًا **منسوب إلى قاعدة

### وV2 يضيف مسارًا رابعًا


**بعد كل مُعدِّل.** فمستند لا يفشل في أي قاعدة حاجبة، درجته الأساسية 45، ومورده
غير معتمَد بعَلَمين (+35) ⇒ **80 ⇒ محجوب**.

### ما يعنيه هذا

| | V1 | V2 |
|---|---|---|
| مصدر الحجب | فشل قاعدة مسمّاة | فشل قاعدة **أو** درجة مركّبة ≥75 |
| قابلية النسبة | «حُجب بسبب `GAAP-COMP-001`» | قد يكون «حُجب لأن المجموع 80» |
| الأثر | — | **حجب بلا قاعدة فاشلة واحدة** |

> **هذا ليس خطر هجرة — إنه تغيير في دلالة التدقيق.**
>
> V2 يستطيع منع اعتماد مستند **دون أن تفشل فيه قاعدة واحدة**. والمدقق الذي
> يُسأل «لماذا حُجب هذا؟» لن يجد قاعدة يشير إليها — سيجد مجموعًا.

**والسؤال ليس «هل الخطوة ٤ آمنة تقنيًا» — بل: هل تقبل مهنيًا أن يُحجب اعتماد
بلا قاعدة منسوبة؟**

هذا قرارك أنت كمدقق، لا قراري كـCTO. وأدرجه في §١ من `EXECUTION_TRACKER`
كثابت مقدّس مرشَّح: **قابلية نسبة الحجب إلى قاعدة**.

## ٢. الإصلاح الذي اقترحتُه هو الذي كسر خمسة اختبارات

في `CTO_DECISION_shipment_4.md` §1 كتبت:

```python
_original = getattr(_gated, "_original", None)
```

**و`MagicMock` يجيب على أي اسم.** فأعاد ابنًا مخترعًا بدل `None`، فلم ينطلق
الاحتياطي، فنُودي `mock._original()`.

```
AssertionError: <MagicMock name='run_audit_compat._original().pk'> != UUID(...)
```

وحلّ المنفّذ أصحّ من حلّي — **تمييز بالهوية لا بوجود سمة**:

```python
_original = _ORIGINAL_RUN_AUDIT if _entry is _GATED_WRAPPER else _entry
```

`getattr` سؤال عن سمة، و`is` سؤال عن **هوية**. والمُحاكيات تكذب في الأول ولا
تكذب في الثاني. الدرس أوسع من هذه الحالة: **في أي شيفرة تُغلَّف أو تُرقَّع،
الهوية هي الفحص الصحيح.**

**وبوابة الدفع أمسكته.** لو كانت البوابة «شغّل اختباراتك» بدل «صفر فشل قبل
الدفع» لدُخل العيب.

## ٣. الحارس الذي لم يكن يستطيع الفشل — والتقطه المنفّذ بنفسه

حارسه الأول استعمل معرّف مستند غير موجود، فـ`_resolve_document_and_org` يرمي
**قبل** بلوغ سطر الارتداد. أي أنه كان يؤكّد «لا ارتداد» عن سطر لم يُنفَّذ —
**ويمرّ ضد الشيفرة المعطوبة**.

اكتشفه بإعادة العيب عمدًا، ثم صحّح الحارس ليبلغ موضع العيب، ثم أعاد الإثبات:

```
معطوب → 2 failed   ·   مُصلَح → 4 passed   ·   17/17 مع القديمة
```

**هذا ثالث حارس في هذا المستودع يُولَد عاجزًا عن الفشل** (`8102cf1` ·
`test_engine_callers` سابقًا · وهذا). النمط ثابت بما يكفي ليصير قاعدة:

> **كل حارس يُثبَت بإعادة إنتاج العيب — لا بزرع مخالف مصطنع فحسب.** المخالف
> المصطنع قد يفشل لسبب آخر غير العيب.

```sql
SELECT d.document_type, COUNT(*) AS total,
       SUM(CASE WHEN po.id IS NULL AND fa.id IS NULL THEN 1 ELSE 0 END) AS shells
FROM documents_document d
LEFT JOIN documents_purchaseorder po ON po.document_id = d.id
LEFT JOIN documents_fixedasset    fa ON fa.document_id = d.id
GROUP BY d.document_type;
```
