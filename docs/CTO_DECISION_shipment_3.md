## ١. أهم ما في التقرير: عيب كنت سأودعه في المستودع

الملفات المُحدَّثة وُضعت في `docs/executor/` لا في المسارات المذكورة. والنسخ
**المتتبَّعة** في `docs/` كانت قديمة:

```
docs/UNIFICATION_STEPS_4_9.md   فارق ٣١ سطرًا  (بلا تصحيح ١١٤)
docs/EXECUTION_TRACKER.md       فارق ٩ أسطر    (صفر انحرافات ٢٤–٢٧)
docs/UNIFICATION_PLAN.md        فارق سطرين

```

**فلولا الفحص، لكان `git add docs/` أودع الوثائق القديمة، والتزم برسالة تصف
تصحيحات ليست فيها.** أي commit يدّعي إصلاح خطأ ولا يحمله.

هذا **أنقى مثال في السلسلة كلها** على العيب الذي نطارده — ولو مررنا به لكان
الدليل على الجذر قد أصبح مثالًا عليه.

**والتصرّف كان صحيحًا:** نسخ المحتوى حرفيًا إلى المسارات الصحيحة، بلا تحرير سطر.

## ٢. 🔴 بوابة الخطوة ٤ كانت مصمَّمة خطأ

علّقتُ الخطوات ٤·٥·٦أ·٦ب على استعلام إنتاج، ثم تبيّن في ثلاث جولات أنه غير
قابل للوصول من جهاز التطوير. **بوابة لا يستطيع أحد اجتيازها ليست بوابة — إنها
توقّف دائم متنكّر في صورة حذر.**

والأسوأ: **كان بإمكاني الإجابة على السؤال من الشيفرة من البداية.** قرأت
المُعدِّلات الأربعة الآن، والنتيجة قاطعة ولا تحتاج بيانات.

### ما تقوله الشيفرة (`pipeline/stages/risk_engine.py`)

| المُعدِّل | الزيادة | شرط الإطلاق |
|---|---|---|
| `VendorRiskModifier` | مورد غير معتمَد **+15** · مجهول **+5** · أعلام **+10 لكل علم بسقف +20** ⇒ **حتى +35** | `vendor_context` غير فارغ |
| `FrequencyModifier` | **+10** | ≥ 50 مستندًا في نافذة المراجعة |
| `ERPContextModifier` | **+20** | المبلغ > حدّ الموازنة |
| `AnomalyModifier` | **+15** (شذوذ ≥70) · **+8** (≥40) | دائمًا يُحاوَل |

### والحقيقتان الحاسمتان

**١. المُعدِّلات أحادية الاتجاه — تزيد ولا تنقص أبدًا.**

```python
new_score = min(float(risk_data.get("risk_score", 0)) + adjustment, 100.0)
```

لا مُعدِّل واحد يُنقص الدرجة. **فدرجة V2 ≥ درجة V1 دائمًا، بلا استثناء.**

**٢. الحدّ الأعلى للفارق: +80 نقطة** (35+10+20+15)، مقيَّدًا بـ100.

**٣. والحجب لاصق:**

```python
if not risk_data.get("blocks_approval"):
    risk_data["blocks_approval"] = new_score >= 75
```

فمستند بدرجة V1 = 55 (`high`) يتجاوز الموازنة ⇒ 75 ⇒ `critical` **ويُحجَب
اعتماده**. وهو اعتماد كان يُمنَح اليوم.

### الحكم على البوابة القديمة

معياري كان: «> 15 نقطة ⇒ توقّف». **الشيفرة تقول إن الحدّ الأعلى 80.**

فالبوابة **مُجابة، وجوابها «أعِد التصميم» لا «امضِ»**. الخطوة ٤ كما كُتبت
ستُنشئ حجبًا جديدًا — والسؤال ليس «هل» بل «على كم مستندًا».

### وما يُنقذ الموقف

المُعدِّلات **لا تنطلق بلا سياق**:

```python
vendor = context.vendor_context
if not vendor:
    return risk_data          # صفر تغيير
```

نفسه في `ERPContextModifier`. فالمستند بلا سياق مورد ولا ERP ⇒ **فارق صفر**.

فالسؤال الحقيقي صار محدّدًا وقابلًا للقياس: **ما نسبة المستندات التي يُبنى لها
سياق مورد أو ERP؟**

## ٣. البوابة الجديدة — على `Dataset/` لا على الإنتاج

عندك في المستودع ما يُجيب السؤال بلا وصول إنتاج: **`Dataset/` — 23 ميغابايت،
ثمانية ملفات Excel وفواتير حقيقية بشذوذ مزروع معروف النسب.**

هذا ما بُنيت له مواصفة المرجع الذهبي أصلًا. لم أربطها بالبوابة، وكان يجب.

### البوابة المعاد تصميمها

شغّل **كلا الأنبوبين** على مجموعة `Dataset/` على أي جهاز فيه قاعدة اختبار،
وقِس ثلاثة أرقام:

| # | القياس | البوابة |
|---|---|---|
| 1 | نسبة المستندات بفارق درجة > 0 | يُسجَّل — للعلم |
| 2 | **عدد المستندات التي `blocks_approval` تنقلب فيها من False إلى True** | **صفر ⇒ امضِ · > 0 ⇒ قرار** |
| 3 | أقصى فارق مُقاس | يُقارَن بالحدّ النظري 80 |

**القياس ٢ هو البوابة الحقيقية.** لا الفارق في المتوسط — فالمتوسط يخفي أن
مستندًا واحدًا انتقل من «يُعتمَد» إلى «محجوب»، وهذا وحده أثر مباشر على عمل
المدقق.

**ولا يحتاج إنتاجًا، ولا حاويات، ولا رمزًا.** جهاز تطوير + `Dataset/` يكفيان.

### والاستعلام على الإنتاج يبقى مطلوبًا — لا كبوابة

فائدته أن يخبرنا كيف تتوزّع الحركة على الأجيال. لكنه **لم يعد يحجب شيئًا**.
شغّله متى توفّر وصول، من الخادم:

```bash
ssh <الخادم>
cd <مسار المشروع>
docker compose -f deployment/docker/docker-compose.yml exec web_live \
  python manage.py shell -c "
from apps.rule_engine.models import AuditRun
from django.db.models import Count, Avg
print(list(AuditRun.objects.values('engine_version')
      .annotate(n=Count('id'), avg=Avg('risk_score'))))
print('TOTAL:', AuditRun.objects.count())"
```

## ٤. قرارات على أسئلتك الثلاثة

### ١. `docs/executor/` — احذفه، بعد تحقّق

```bash
# تأكّد أن المتتبَّع = ما في executor قبل الحذف
for f in CLAUDE.md UNIFICATION_STEPS_4_9.md EXECUTION_TRACKER.md \
         UNIFICATION_PLAN.md CTO_DECISION_shipment_1.md CTO_DECISION_shipment_2.md; do
  a=$(find . -path ./docs/executor -prune -o -name "$f" -print | head -1)
  b="docs/executor/$f"
  [ -f "$a" ] && [ -f "$b" ] && \
    printf "%-34s %s\n" "$f" "$(diff -q "$a" "$b" >/dev/null && echo متطابق || echo '*** مختلف ***')"
done
```

كلها متطابقة ⇒ `rm -rf docs/executor/`
أيّها مختلف ⇒ **توقّف وأبلِغ** — النسخة المتتبَّعة قد تكون الناقصة.

**والازدواج الذي أنتجه المنفّذ سجّله على نفسه في §7.** هذا هو المعيار المطلوب.

### ٢. الرمز — الحاجز الوحيد الباقي أمام الدفع

خمسة commits جاهزة، والتصريح سليم ويذكر `claude` صراحةً. **الحاجز إجراء يستغرق
دقيقة:** `github.com/settings/tokens` ← Revoke · ثم `Settings → Security log`.

هذا الشرط لا أُسقطه. ولاحظ أن الرمز كان مكشوفًا حين ظهر
`origin/chore/unify-audit-engines` من مصدر غير محدَّد.

### ٣. ملف القفل — يحتاج الخادم

`docker compose` غير مثبَّت على جهاز التطوير (Docker موجود، الإضافة لا).
فالتوليد يجري على الخادم بنفس أمر §3 أعلاه، مستبدلًا الأمر الأخير بـ
`python -m pip freeze`.

**لا بديل من جهاز التطوير** — نصف الحزم غير مثبَّتة فيه.
