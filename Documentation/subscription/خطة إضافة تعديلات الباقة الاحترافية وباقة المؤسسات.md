# خطة إضافة تعديلات الباقة الاحترافية وباقة المؤسسات

## 1. الوضع الحالي

يحتوي الملف الحالي على ست باقات: المجانية، الأساسية، المتوسطة، الأعمال، الاحترافية، والمؤسسات. ويعرض جدولًا يقارن بين عدد المستخدمين، عدد الفواتير، تدقيق الفواتير، الذكاء الاصطناعي، التقارير، لوحات المؤشرات، التنبيهات، الصلاحيات، سجل العمليات، التكاملات، سير الموافقات، الأرشفة، النسخ الاحتياطي، الدعم، التدريب، تخصيص التقارير، والعلامة التجارية.

المشكلة الأساسية هي أن باقة المؤسسات تظهر حاليًا بوصفها مستوى أعلى من الباقة الاحترافية، لكنها لا توضّح بما يكفي أنها حل مؤسسي مستقل له متطلبات تشغيل وحوكمة واستضافة وتخصيص مختلفة. كما أن المزايا الجديدة المقترحة للباقة الاحترافية تحتاج إلى إضافتها في صفوف مستقلة بدل وضعها داخل وصف عام للذكاء الاصطناعي أو التقارير.

## 2. المبدأ الصحيح للتعديل

يجب التعامل مع التعديل على أنه **إعادة هيكلة لجدول المزايا** وليس مجرد إضافة نصوص في نهاية الجدول. وينبغي أن تظل الباقة الاحترافية منتجًا جاهزًا بسعر واضح قدره 999 ريال، بينما تكون باقة المؤسسات حلًا مخصصًا يُسعّر حسب نطاق المشروع وعدد الشركات والتكاملات ومتطلبات الاستضافة ومستوى الدعم.

## 3. الإضافات المقترحة للباقة الاحترافية

تُضاف المزايا التالية كصفوف مستقلة في جدول المقارنة، وتُفعّل في عمود الباقة الاحترافية:

| الميزة الجديدة | طريقة عرضها في الجدول | النطاق المقترح |
|---|---|---|
| شرح أسباب رفض الفاتورة بالذكاء الاصطناعي | تفسير ذكي لأسباب الرفض والإجراء المقترح | مشمول |
| مقارنة الأسعار مع السوق | مقارنة سعر البند ببيانات السوق أو النطاق المرجعي المتاح | مشمول ضمن حدود الاستخدام العادل |
| توقع الفواتير المشبوهة قبل اعتمادها | تنبيه استباقي قبل الموافقة، مع درجة اشتباه وسببها | مشمول |
| تنبيهات تجاوز الميزانية | تنبيهات عند الاقتراب من الميزانية أو تجاوزها | مشمول |
| تقارير تنفيذية لمجلس الإدارة | تقارير ملخصة ومؤشرات تنفيذية قابلة للتصدير | مشمول |
| API كامل | واجهات تكامل موثقة مع مفاتيح وصلاحيات واستخدام محدد | مشمول |
| ربط Odoo وERP | موصلات جاهزة للأنظمة المدعومة | Odoo مشمول، والأنظمة الأخرى حسب التوافق أو كخيار إضافي |
| مدير حساب مخصص | نقطة اتصال لإدارة الحساب والمتابعة | مشمول |
| تدريب مباشر للفريق | جلسات تدريب مباشرة عن بُعد أو حسب نطاق متفق عليه | مشمول بعدد جلسات محدد |

يُفضّل إضافة ملاحظات تشغيلية داخل صفحة الأسعار، مثل عدد جلسات التدريب، حدود استخدام واجهة API، والأنظمة المدعومة، حتى لا تبدو كلمة «كامل» التزامًا مفتوحًا وغير محدد.

## 4. إعادة تعريف باقة المؤسسات

ينبغي تقديم باقة المؤسسات كحل مؤسسي مستقل، لا كنسخة موسعة من الباقة الاحترافية. وتكون رسالتها: **منصة مخصصة للمؤسسات متعددة الشركات والفروع، مع حوكمة واستضافة وتكامل ودعم على مستوى المؤسسة**.

| المحور | باقة المؤسسات |
|---|---|
| السعة | مستخدمون وفواتير غير محدودين، وفق سياسة الاستخدام العادل والقدرة المتفق عليها |
| الهيكل المؤسسي | فروع وشركات متعددة مع عزل البيانات وإدارة مركزية |
| الحوكمة | موافقات متعددة المستويات وصلاحيات متقدمة وسجل عمليات مؤسسي |
| الهوية | White Label باسم العميل وهوية بصرية مخصصة |
| الاستضافة | Private Cloud أو On-Premise وفق متطلبات العميل |
| الذكاء الاصطناعي | نماذج وقواعد مخصصة حسب نشاط الشركة وبياناتها وسياساتها |
| التقارير | تقارير ولوحات مؤشرات مخصصة بالكامل |
| التكامل | تكامل مع أي نظام ERP أو API بعد التحليل الفني |
| مستوى الخدمة | اتفاقية SLA بمؤشرات استجابة وتوافر ودعم 24/7 |
| التنفيذ | مدير مشروع مخصص وخطة تنفيذ ومراحل قبول واضحة |
| التمكين | تدريب واستشارات دورية للفريق |

## 5. ما يجب نقله أو إعادة صياغته من الجدول الحالي

تظل الحدود الرقمية مثل 25 مستخدمًا و5,000 فاتورة مناسبة للباقة الاحترافية إذا كانت سياسة المنتج تعتمد هذه الحدود. أما في باقة المؤسسات فيُستبدل العرض الرقمي بعبارة «غير محدود» مع إضافة ملاحظة تعاقدية عن سياسة الاستخدام العادل.

ويجب فصل «API» عن «ربط ERP». فالـ API يصف قدرة تقنية عامة، بينما ربط ERP يصف خدمة تنفيذ وتكامل. كما يجب فصل «تخصيص التقارير» عن «التقارير التنفيذية لمجلس الإدارة»، لأن الأولى تخص تصميم التقارير، والثانية تخص نوعًا محددًا من مخرجات الإدارة العليا.

كذلك ينبغي توسيع صف «سير عمل الموافقات» ليبيّن الفرق بين الموافقات المتاحة في الباقات العادية وبين «الموافقات متعددة المستويات» في المؤسسات. ويضاف صف مستقل للاستضافة الخاصة، وصف مستقل لاتفاقية مستوى الخدمة، وصف مستقل لمدير المشروع، وصف مستقل للدعم 24/7.

## 6. خطة التنفيذ بالترتيب الصحيح

### المرحلة الأولى: اعتماد تعريف المنتجات

يُعتمد أولًا أن الاحترافية باقة جاهزة بسعر 999 ريال، وأن المؤسسات باقة مخصصة بسعر «يبدأ من» أو «حسب الطلب». كما تُحدد حدود كل ميزة قبل إدراجها في صفحة الأسعار.

### المرحلة الثانية: تحديث مصفوفة المزايا

تُضاف الصفوف الجديدة إلى الجدول، ثم تُراجع جميع الخانات بحيث لا تتكرر المزايا أو تتعارض. ويجب استخدام تسميات موحدة مثل «مشمول»، «خيار إضافي»، «حسب الطلب»، و«غير متاح».

### المرحلة الثالثة: تحديد النطاق التجاري والتشغيلي

تُوثّق حدود التدريب، واستخدام API، ومقارنة الأسعار مع السوق، وعدد مصادر بيانات السوق، ونطاق دعم ERP، ووقت الاستجابة، وسياسة الاستخدام العادل. هذه الخطوة مهمة خصوصًا للمزايا التي قد تُفهم على أنها غير محدودة.

### المرحلة الرابعة: تحديث واجهة الأسعار والرسائل التسويقية

تُعرض الاحترافية كباقة ذات قيمة تشغيلية وذكاء متقدم، بينما تُعرض المؤسسات كحل للتحول المؤسسي والحوكمة والتخصيص. ويُفضّل وضع زر «اطلب عرضًا مخصصًا» للمؤسسات بدل وضع سعر ثابت.

### المرحلة الخامسة: التحقق قبل الإطلاق

يُراجع الجدول من فرق المنتج، والمبيعات، والتقنية، والدعم، والشؤون القانونية أو التعاقدية. ثم تُختبر رحلة العميل: اختيار الباقة، فهم المزايا، معرفة الحدود، طلب العرض، وتحديد ما إذا كانت الميزة جاهزة أو تحتاج تنفيذًا مخصصًا.

## 7. النتيجة التجارية المطلوبة

بعد التعديل، يجب أن يكون الفرق واضحًا في ثلاث طبقات:

| الباقة | الوعد الأساسي |
|---|---|
| الاحترافية – 999 ريال | ذكاء متقدم وأتمتة وتقارير وتكاملات جاهزة لفريق أو شركة واحدة ضمن نطاق واضح |
| المؤسسات – حسب الطلب | بنية مؤسسية كاملة تشمل تعدد الشركات والفروع، الاستضافة الخاصة، التخصيص، الحوكمة، التكاملات، وSLA |

بهذا الأسلوب لا تكون باقة المؤسسات مجرد قائمة أطول، بل منتجًا مختلفًا من حيث البنية، وطريقة الشراء، والتنفيذ، والدعم، والمسؤوليات التعاقدية.
