# ١. ترتيب المسارات — أهش ما في المشروع

## ١.١ الواقع

```
finai_backend/urls.py
  السطور 48–59    api/v1/*        ← قبل الواجهة ✅
  السطر  92, 100  platform-admin/ ← "IMPORTANT: must come before the catch-all"
  السطر  107      path('', include('apps.frontend.urls'))   ← 150 مسارًا على الجذر
  السطر  113      dashboard/  →  vendor_dashboard
  السطور 116–125  api/v1/invoices, reports, rule-engine, …  ← 🔴 بعد الواجهة
```

**36 ملف `urls.py` · 150 مسارًا في الواجهة وحدها.**

## ١.٢ 🔴 ثلاثة ثوابت لا تُخالَف — كسرها يُسقط النظام صامتًا

### الثابت ١ — `/dashboard/` يعمل بالحظّ لا بالتصميم

`frontend/urls.py` يعرّف `dashboard/` **مسارًا مضبوطًا (exact)**، و`vendor_dashboard`
يُركَّب على `dashboard/` **بعده**. فالتحليل:

```
/dashboard/         →  frontend:dashboard
/dashboard/files/   →  vendor_dashboard:*
```

> **ويكفي أن يحوّل أحدٌ `dashboard/` في الواجهة إلى `include` أو يضيف
> `dashboard/<...>`، لتختفي لوحة المنظمة بالكامل — بلا خطأ ولا استثناء، فقط
> صفحات لا تُوجَد.**

**قبل أي لمس لمسار يبدأ بـ`dashboard/`:** اقرأ التعليق في
`finai_backend/urls.py:104-106` — هو التحذير الوحيد القائم، ولا يحرسه اختبار.

### الثابت ٢ — واجهات API بعد الواجهة الشاملة

`api/v1/invoices` · `reports` · `rule-engine` · `notifications` · `assistant` ·
`webhooks` · `partners` · `export` — **كلها مسجَّلة بعد السطر 107.**

والواجهة تعرّف `api/` (صفحة تسويقية) مضبوطًا فقط، فالتصادم لا يقع اليوم.

> **وأي نمط بادئة جديد في الواجهة يبدأ بـ`api/` يُسقط ثماني مجموعات API.**

### الثابت ٣ — `platform-admin/` قبل الشاملة

موثَّق بتعليق `IMPORTANT` في الملف. **بلا اختبار.**

## ١.٣ الحارس الناقص — يُكتب مرة ويحمي دائمًا

`tests/test_url_resolution.py` — يُثبّت المسارات الحرجة بـ`resolve()`:

```
resolve("/dashboard/")        →  frontend:dashboard
resolve("/dashboard/files/")  →  vendor_dashboard:*
resolve("/platform-admin/")   →  platform_admin:*
resolve("/api/v1/invoices/")  →  invoices (لا الواجهة)
resolve("/api/v1/audit/run/") →  audit
resolve("/api/")              →  frontend (الصفحة التسويقية)
```

**ثلاثة تعليقات `IMPORTANT` في `urls.py` تحمي النظام اليوم — والتعليق لا يفشل.**
هذا الاختبار يحوّل الثوابت الثلاثة من نيّة إلى حارس.

for f in blocks_approval risk_level risk_score total_rules validation_score; do

# ٣. الأثر المعروف لكل تغيير مُخطَّط

## ٣.١ ✅ دلالة الحجب — أصلحت عيبًا في الواجهة

`templates/reports/document_audit_report.html`:

```django
السطر 277:  {% if summary.blocks_approval %}  🔒 Blocks Approval
السطر 672:  {% if rule.blocks_approval %}     🔒        ← لكل قاعدة
```

**الواجهة تعرض قفلًا لكل قاعدة.** فقبل الإصلاح، مستند حُجب بالدرجة كان يُظهر
«🔒 يحجب الاعتماد» في الملخّص و**صفر أقفال في جدول القواعد** — فالمدقق يبحث عن
القاعدة الحاجبة ولا يجدها.

> **الواجهة كانت مبنيّة على الفهم الصحيح من البداية. والخلفية هي التي خالفته.**

## ٣.٢ 🔴 المرحلة ١ب — العدّادات تقفز

اليوم `AuditRun` **لا يُنشأ إطلاقًا** لأنواع المستندات الأحد عشر
(`Document.DoesNotExist`). وبعد الإصلاح تُنشأ.

فكل ما يقوم على `AuditRun.objects.filter(organization=org)` يقفز فجأة: عدّادات
«المستندات المُدقَّقة» · توزيع المخاطر · الرسوم.

**ما يجب فعله:** لقطة قبل/بعد للوحة · وإشعار للمدققين **قبل** النشر.

## ٣.٣ 🔴 الخطوة ٤ — نسبة الامتثال تنكسر تاريخيًا

`apps/frontend/page_views.py:4341-4355`:

```python
agg = runs.aggregate(total_rules=Sum("total_rules"), passed=Sum("passed_rules"), …)
re_compliance = round((re_passed / re_total_rules) * 100, 1)
```

مسار المستندات ينتقل من **18 قاعدة إلى 131** ⇒ **المقام يتضاعف سبع مرات.**

> **لوحة تقول «الامتثال 94%» ستقول رقمًا آخر بلا أن يتغيّر شيء في جودة
> المستندات.** والمقارنة بالفترات السابقة تصير بلا معنى.

**المطلوب مع الخطوة ٤:** خطّ فاصل عند تاريخ النشر، أو تصفية بـ`engine_version`
(`"2.0"` مقابل `"3.0"`). **وهذا بند لم يكن في أي خطة قبل اليوم.**

## ٣.٤ ⚠️ مُعدِّلات V2 — 32 قالبًا تعرض مستوى قد يرتفع

حُذف الحجب بالدرجة، **وبقيت المُعدِّلات تحرّك `risk_score` و`risk_level`**.
فمستندات ستنتقل من `high` إلى `critical` في العرض **بلا أن تُحجَب**.

**سلوك مقصود** — ترتيب المخاطر يتحسّن ولا يُمسّ الاعتماد. **ويحتاج شرحًا
للمدقق**، وإلا قرأه تدهورًا في جودة مستنداته.

# ٤. أسطح لا تنسها

## ٤.١ استدعاءات JS للـAPI من القوالب — 20+ نقطة

منها ما يمسّ التدقيق مباشرة:

```
/api/v1/audit/run/            /api/v1/audit/results/
/api/v1/audit/jobs/           /api/v1/audit/jobs/stats/
/api/v1/audit/rule-builder/   /api/v1/analytics/live/
```

**أي تغيير في شكل الاستجابة يكسر JS صامتًا** — لا استثناء في السجل، فقط شاشة لا
تُحدَّث. وهذه أسوأ حالة: العميل يرى واجهة تعمل وتحمل بيانات بائتة.

## ٤.٢ نقطة الاستقصاء الحيّة

`/api/v1/analytics/live/` تُستدعى دوريًا (حلّت محلّ WebSocket). **تكرار الاستدعاء
يعني أن كسرها يظهر في كل شاشة مفتوحة.**

## ٤.٣ العربية وRTL

تغيير أي نصّ معروض يحتاج `makemessages` + `compilemessages`. **رسالة جديدة بلا
ترجمة تظهر بالإنجليزية في واجهة عربية** — ويظهر ذلك للعميل فورًا.

## ٤.٤ CSP و`unsafe-eval`

حذفه كسر **كل صفحة تستخدم Alpine** على الإنتاج: الصفحات ترجع `200` **وهي
جامدة**. `grep` على الترويسة لا يكشف ذلك — **فتح متصفّح يكشفه.**

# ٥. قائمة ما قبل النشر — إلزامية لأي تغيير يمسّ §٢

```
[ ] ١. أعِد قياس خريطة §٢ — الأرقام تتقادم
[ ] ٢. لكل حقل متأثّر: اقرأ القوالب التي تستعمله بعينك
[ ] ٣. pytest tests/test_url_resolution.py         ← اكتبه إن لم يوجد
[ ] ٤. افتح الصفحات الستّ الحرجة في متصفّح — لا بـcurl:
       /dashboard/  ·  /invoices/  ·  /reports/<id>/  ·  /dashboard/files/
       /platform-admin/  ·  صفحة تقرير تدقيق كاملة
[ ] ٥. تحقّق من صفحة تستخدم Alpine — تفاعلها لا وجود عنصرها
[ ] ٦. راقب console المتصفّح: صفر خطأ JS
[ ] ٧. لقطة قبل/بعد للوحة الرئيسية — الأرقام والرسوم
[ ] ٨. تغيّرت الأرقام؟  ⇒  إشعار المدققين **قبل** النشر لا بعده
[ ] ٩. نصّ جديد؟  ⇒  makemessages + compilemessages
[ ] ١٠. اختبر بحساب مؤسسة عادية — لا بحساب مشرف
```

**البند ٤ لا يُختصر.** «الترويسة صحيحة» ليست «الصفحة تعمل» — وهذا خطأ موثَّق في
`8c2f9cb`: «تحققت من الترويسة ولم أفتح متصفحًا قط».

**والبند ٨ أشدّ أثرًا من أي عيب تقني أصلحناه:** مدقق يرى أرقامه تتغيّر بلا إشعار
يفقد الثقة في المنصّة.
