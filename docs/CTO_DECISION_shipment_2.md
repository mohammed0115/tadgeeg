## ١. خطأ حوكمة — مسؤوليتي وحدي

ولو نفّذ إحداهما لكان مخالفًا للأخرى.

والتناقض ليس فنيًّا فقط: قرار الشحنة ١ نفسه يقول إن سحب الرمز المكشوف **يسبق كل
ما في الملف** — والمنفّذ لاحظ أن الدفع قبله يخالف ترتيب قراري.

### التصحيح — بند ١ يُستبدَل نصّه في `CLAUDE.md`

```
1. لا `git push` إلا بتصريح مكتوب في ملف قرار CTO يذكر اسم الفرع صراحةً.
   بلا تصريح: لا دفع، ولا إلى فرع فرعي.
   عند تعارض تعليمتين: توقّف واسأل — ولا ترجّح من تلقائك.
   ملف القرار الأحدث تاريخًا يعلو على العقد العام عند التعارض الصريح.
```

**قاعدة دائمة:** العقد العام يقول «لا»، وملف القرار يفتح استثناءً مسمّى. لا
استثناء شفهي.

## ٢. اعتراضات المنفّذ — تحققت منها بنفسي

### ✅ صحيح — عدد ملفات `Docs/` هو ١١٤ لا ١١٣

```
git ls-files | grep -c "^Docs/"           →  113
git ls-tree -r --name-only HEAD -- Docs   →  114
```

السبب مؤكَّد: `git ls-files` **يقتبس** المسارات ذات المحارف غير اللاتينية،
فتبدأ بعلامة تنصيص لا بحرف `D` ولا يراها `grep "^Docs/"`. رأيت الأمثلة في
`Dataset/` بأسماء عربية مُرمَّزة ثمانيًا.

**وهذا خطأ مني من الصنف الذي أطارده:** كتبت رقمًا بأداة لم أتحقّق من سلوكها.
والقياس المحصَّن الذي اقترحه المنفّذ هو الصحيح.

### ✅ صحيح — أمر `sed` كان سيُفسد نفسه

`docs/UNIFICATION_STEPS_4_9.md` يحتوي `Docs/` سبع مرات، منها:

```
السطر 279:  git ls-files | grep -c "^Docs/"   →  113
السطر 290:  git mv Docs Documentation
```

فتشغيل `sed` كان سيحوّلهما إلى `grep -c "^Documentation/"` و
`git mv Documentation Documentation`. **التعليمات تُدمّر نفسها.**

اكتشافه بالفحص المسبق قبل التنفيذ هو ما يُفترض أن يفعله منفّذ جيد.

### ⚠️ لم أستطع تأكيده — الاستثناء في أمري

في بيئتي `grep -rl "Docs/" --include="*.md" .` يُخرج بادئة `./`، والاستثناء
`grep -v "^./Documentation/"` **يعمل**: من 31 ملفًا يستبعد إلى 13.

لا أستطيع تأكيد أنه فشل عندك، ولا أنفيه. **لكن النتيجة التي أبلغت عنها (١٨
ملفًا داخل `Documentation/` أُعيدت كتابتها) متّسقة مع فشله.** والدرس أهم من
الآلية: **أمر `sed -i` بلا فحص مسبق ولا نسخة احتياطية لا يُوثَّق في خطة.**

الصيغة المصحَّحة — تستثني الوثائق التي تصف العملية، وتُظهر ما ستمسّه قبل أن تمسّه:

```bash
# ١. اعرض ما سيُمسّ — ولا تُنفّذ بعد
grep -rl "Docs/" --include="*.py" --include="*.md" --include="*.sh" . \
  | grep -v "/Documentation/" \
  | grep -v "docs/UNIFICATION_" \
  | grep -v "docs/CTO_DECISION"

# ٢. راجع القائمة بعينك، ثم:
#    <القائمة أعلاه> | xargs sed -i 's|Docs/|Documentation/|g'
```

### ✅ صحيح — الحزم الخمس غير المثبَّتة

`boto3` · `chardet` · `django-storages` · `mysqlclient` · `xlrd` غير مثبَّتة
في بيئتك، فلا يمكن قياس نسخها. **رفضُ قفل نسخة لم تُقَس هو تطبيق صحيح للعقد**،
لا تلكّؤ. ملف قفل يحمل نسخة مُخمَّنة أسوأ من ملف ناقص — يبدو موثوقًا وليس كذلك.

### ✅ صحيح — TLS ليس عملًا مستودعيًا

صفر ملفات شهادات متتبَّعة منذ `4f4da4f`. المتبقّي إبطال وتدوير على الخادم
والـCA — خارج وصولك، **وعليّ أنا أن أُخرجه من قوائم مهامك**. تصنيفك صحيح.

### ✅ وتصحيحك لنفسك

قلت «١٥ مرجعًا لا ١٣» ثم رجعت وأثبتّ أن رقمي صحيح. **تصحيح المنفّذ لنفسه علنًا
أثمن عندي من إصابته من أول مرة** — ويُسجَّل كما يُسجَّل خطئي.

## ٤. أجوبة على أسئلتك الخمسة

### ١. الدفع

**نعم — ادفع، بشرطين مسبقين:**

- ✅ الرمز المكشوف مسحوب (`github.com/settings/tokens`)
- ✅ `Settings → Security log` مُراجَع لأي دفع لم تُجرِه

```bash
git push -u origin claude
```

ثم PR إلى `main`. اذكر في وصفه أن `origin/chore/unify-audit-engines` يحمل
المحتوى نفسه وسيُحذف بعد الدمج.

**التصريح مكتوب هنا باسم الفرع صراحةً** — بالصيغة الجديدة لبند ١.

### ٢. الـ١٨ ملفًا داخل `Documentation/`

**أصلحها.** روابط داخلية معطوبة اليوم، وإصلاحها آمن ومحصور:

```bash
grep -rl "Docs/" Documentation/ | xargs sed -i 's|Docs/|Documentation/|g'
grep -rn "Docs/" Documentation/ | head
```

الوثائق تصف النظام، ووثيقة تشير إلى مسار غير موجود هي بالضبط ما نطارده.

### ٣. ملف القفل

**الطريقة التي اقترحتها هي الصحيحة** — تُولَّد حيث الحزم مثبَّتة فعلًا:

```bash
docker compose -f deployment/docker/docker-compose.yml exec web_live \
  python -m pip freeze > requirements.lock.txt
```

**لا تُضف الخمس المقيسة وحدها.** ملف نصفه محسوب ونصفه مُقدَّر أسوأ من ناقص
معروف نقصُه.

⚠️ من `web_live` تحديدًا — هي البيئة التي تحمل ما يعمل فعلًا. وبعدها:
`pip-audit -r requirements.lock.txt` وأرسل الناتج.

### ٤. Django 5.2

**شحنة مستقلة، بعد القفل.** الترتيب: القفل → الترقية وحدها → المجموعة الكاملة
→ `check --deploy`. لا تُدمج مع شيء.

والحاجز الوحيد معروف: ثلاثة مواضع `STATICFILES_STORAGE`/`DEFAULT_FILE_STORAGE`
أُزيلت في 5.1، والنمط الصحيح موجود عندك في `finai_backend/settings/test.py:21`.
