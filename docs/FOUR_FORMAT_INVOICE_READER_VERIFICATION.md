# التحقق النهائي لقارئ الفواتير بأربع صيغ

## النطاق

يتحقق هذا التقرير من طبقة **قارئ الفواتير واستخراج الحقول** لملف واحد متطابق المحتوى بصيغ JSON وXLSX وPDF وPNG. لا يدّعي أن مشكلة واجهة الرفع الموثقة سابقاً (الرفع الواحد الذي أنشأ فاتورتين) قد حُلّت؛ ذلك عيب منفصل في طبقة الواجهة/التدفق ولا يُخلط مع القارئ.

## القيم المرجعية

| الحقل | القيمة |
|---|---|
| رقم الفاتورة | `XFMT-2026-001` |
| المورد | `Cross Format Supplier Ltd` |
| الرقم الضريبي | `310123456700003` |
| التاريخ | `2026-08-15` |
| العملة | `SAR` |
| subtotal / VAT / الإجمالي | 1000 / 150 / 1150 |

## النتيجة

| الصيغة | مسار القراءة | صفوف/نجاح | الحقول الثمانية |
|---|---|---:|---|
| JSON | structured upload | سجل واحد | متطابقة |
| XLSX `Field | Value` | structured upload | سجل واحد | متطابقة مالياً؛ تمثيل `1000` يساوي `1000.0` عشرياً |
| PDF | `pdf_text_layer` ثم fallback | ناجح | متطابقة |
| PNG | `ocr_fallback` بعد جاهزية Tesseract | ناجح | متطابقة |

يقارن الفحص المبالغ كقيم عشرية، فلا يخلط فرق العرض النصي بين `1000` و`1000.0` باختلاف مالي. لم تسجل أي صيغة حقلاً مفقوداً أو شظية `oice` أو مبلغاً صفرياً في العينة.

## ما ثُبّت في الشحنات

1. بيانات المحلل تسبق fallback ولا تمحى به.
2. كائن JSON المفرد يصبح سجلاً منظماً واحداً.
3. ورقة XLSX ذات الرأسين `Field | Value` تصبح فاتورة واحدة.
4. رقم PDF لا يلتقط عنوان `TAX INVOICE` بدلاً من المعرف.
5. حارس PNG يشغل Tesseract الحقيقي بلا skip أو Mock، ويجعل غياب الاعتماد فشلاً صريحاً.

## حدود الدليل

هذا دليل قارئ ملفات متكرر على عينات معروفة. ما زال فشل OpenAI (`NoneType`) مسجلاً، لكنه لم يعد يمحو قيمة محلل سليمة. كما أن رفع الواجهة الكامل يحتاج شحنة منفصلة لمعالجة تكرار الفاتورة وتشغيل الخلفية غير المتزامن قبل الادعاء بأن واجهة المستخدم سليمة تماماً.
