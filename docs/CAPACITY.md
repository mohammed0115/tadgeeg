# السعة — غير مقيسة، وهذا سبب ذلك

> **الحالة:** 🔴 **لا رقم.** المرحلة ١ توقّفت عند فحص الأداة قبل التشغيل.
> **التاريخ:** 2026-08-09 · **الفرع:** `claude`

السؤال المطلوب: **كم مستندًا في الدقيقة، وعند كم مستخدمًا متزامنًا.**
الجواب اليوم ما زال «لا نعرف» — ولم أُنتج رقمًا، لأن إنتاج رقم هنا كان
سيعني الإجابة على سؤال غير المطروح.

---

## ١. العائق الأول: الأداة لا تقيس المستندات

`deployment/loadtest/audit_pipeline.py` — اسمه ووثيقته يعدان بقياس أنبوب
التدقيق. توثيقه يقول حرفيًا إنه «يقود كتابات حقيقية عبر أنبوب التدقيق ويستهلك
حصّة الفواتير للمستأجر».

**لا يفعل أيًّا من ذلك.** كل استدعاءات HTTP فيه:

| السطر | الاستدعاء |
|---|---|
| 83 | `GET /login/` |
| 85 | `POST /login/` ← **الكتابة الوحيدة** |
| 104 | `GET /api/v1/analytics/live/` |
| 115 | `GET /dashboard/` |
| 120 | `GET /invoices/` |
| 126 | `GET /vendors/` |
| 130 | `GET /reports/` |
| 138 | `GET /api/v1/reports/` |
| 147 | `GET /api/v1/reports/<id>/pdf/` |
| 172 | `GET /api/v1/analytics/live/` |

صفر رفع ملف · صفر تشغيل تدقيق · صفر استهلاك حصّة. الأداة تقيس **قراءة
صفحات**، لا **إنتاجية مستندات**.

تشغيلها كان سيُنتج رقمًا سليمًا حسابيًا عن «طلبات القراءة في الثانية»، ثم
يُقرأ كأنه «مستندات في الدقيقة». هذه بالضبط طريقة فشل أدوات القياس الثلاث
السابقة في هذه السلسلة.

**ما هو صحيح فيها:** رفضُ الإنتاج ليس ادّعاءً في تعليق — `_refuse_to_run_blind`
(السطر 58) يرمي `SystemExit` ما لم يحتوِ المضيف `dev.` أو `test.` أو
`localhost`، ويرفض العمل بلا `LOADTEST_EMAIL`/`LOADTEST_PASSWORD`. والاعتماد
من البيئة لا من ملف. هذا الجزء منها موثوق.

**ومسألة المعرّف لا تنطبق:** الخطأ الذي أبطل قياس الشحنة ٤ (تمرير
`Document.id` بدل مفتاح السجل المُصنَّف) غير موجود هنا — لكن فقط لأن الأداة
لا تمسّ ذلك المسار إطلاقًا.

## ٢. العائق الثاني: لا بيئة قياس

| المكوّن | الحالة |
|---|---|
| `locust` | **غير مثبَّت** — `ModuleNotFoundError: No module named 'locust'` |
| Redis | **لا عملية** · `CELERY_BROKER_URL = redis://localhost:6379/0` |
| عامل Celery | **لا عملية** · `CELERY_TASK_ALWAYS_EAGER = False` |
| Docker | **صفر حاويات** · إضافة `compose` غير مثبَّتة |
| خادم ويب | لا شيء يستمع على `:8000` |
| SSH لخادم dev | لا — `~/.ssh/config` يحوي `github.com` وحده |
| العتاد | **نواتان** · 12GB ذاكرة (7GB متاحة) |
| قاعدة البيانات | SQLite (`db_runtime.sqlite3`) — الإنتاج MySQL 8.4 |

الخيارات الثلاثة المطروحة:

- **(أ) خادم dev بحاويات** — لا وصول.
- **(ب) `docker compose` محليًا** — الإضافة غير مثبَّتة.
- **(ج) `runserver` + قاعدة محلية** — ممكن بعد تثبيت `locust`، لكنه يقيس
  **SQLite على نواتين بلا Celery ولا Redis**. ومسار التدقيق غير متزامن عبر
  Celery؛ بلا عامل، الطابور لا يُستهلك أصلًا، فقياس «مستندات/دقيقة» عليه
  يقيس سرعة وضع رسائل في طابور لا أحد يقرؤه.

## ٣. ما لم يُقَس، صراحةً

- مستندات/دقيقة عند أي مستوى تزامن
- نقطة الانكسار
- p50 · p95 · p99 تحت الحمل
- استعلامات لكل طلب تحت الحمل
- طول طابور Celery
- استهلاك CPU/ذاكرة تحت الحمل

**والأعناق الخمسة المشتبهة لم يثبت منها ولم ينتفِ أيٌّ** — لا إثباتًا ولا نفيًا:

1. المعالجة المتزامنة على مسار الفواتير
2. ~12 استعلامًا لكل فاتورة
3. التدقيق المزدوج بمحرّكين
4. 645 استعلامًا في 70 وحدة عرض
5. MySQL واحد بلا نسخ قراءة

قراءة الشيفرة ترشّحها؛ لا شيء هنا يرقّيها من ترشيح إلى قياس.

## ٤. ما يلزم لإنتاج الرقم

مرتّبًا بالأثر:

1. **مهمة رفع مستند في أداة الحمل.** بدونها لا علاقة للأداة بالسؤال.
   المسار الإنتاجي: رفع ⇒ `documents/signals.py:137` يُرسل `instance.pk`
   للسجل المُصنَّف ⇒ مهمة Celery ⇒ الأنبوب.
2. **بيئة بـCelery وRedis وMySQL.** خادم dev بحاويات، أو
   `docker compose` محليًا.
3. **`pip install locust`** في تلك البيئة.
4. **مستأجر للاختبار بحصّة كافية** — وإلا فالقياس يتحوّل إلى قياس مسار 402
   كما تحذّر الأداة نفسها.

⚠️ عائق إضافي مسجَّل في الشحنة ٨ ويمسّ أي قياس عبر النقطة الرسمية:
`run_audit_compat` يمرّ ببوّابة الحصّة، والبوّابة تقرأ `document_id` كمفتاح
`Document` بينما كل مُطبِّع يقرؤه كمفتاح السجل المُصنَّف. مقيسًا: `id ==
document_id` في **صفر** من ٥٠٠ صفًّا لكلٍّ من `PurchaseOrder` و`FixedAsset`.
فأي رفع يمرّ بالبوّابة يُعيد `Document.DoesNotExist`. **يُصلَح قبل قياس
الإنتاجية، وإلا فالقياس يقيس عطلًا.**
