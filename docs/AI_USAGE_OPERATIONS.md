# تشغيل وقياس استخدام الذكاء الاصطناعي

## الغرض والنطاق

هذه الشحنة تجعل كل نداء إنتاجي إلى مزود الذكاء الاصطناعي يمر عبر `core.ai.gateway`. ترفض البوابة النداء بلا منظمة، وتستخدم حارس الميزانية القائم، ثم تسجل نتيجة واحدة قابلة للمراجعة في `AIUsageRecord`. تحفظ `AIUsagePayload` تشخيصاً محدوداً ومنقّى؛ لا تحفظ مفاتيح أو ترويسات تفويض أو وسائط base64، وتحذف مهمة Celery اليومية الحمولات بعد مدة الاحتفاظ. لا تُحذف سجلات الاستخدام أو الكلفة بواسطة تلك المهمة.

> **قاعدة تشغيلية:** لا تنفذ نداء AI بلا مالك منظمة، ولا تفسر وجود مفتاح أو حقل إعداد على أنه نجاح للمزود. النجاح يثبت فقط بسجل `AIUsageRecord(status="success")` يحمل رموزاً وكلفة بعد نداء فعلي.

## الإعداد

يحمل النشر المفتاح من متغير البيئة `OPENAI_API_KEY` في ملف أسرار Docker الحي `deployment/docker/env/live.env`. لا يوضع المفتاح في الشفرة أو ملفات المثال أو Git. يمكن ضبط جدول الأسعار ومدة التشخيص بهذه المتغيرات:

| المتغير | المعنى | القيمة الافتراضية |
|---|---|---:|
| `AI_USAGE_GPT5_NANO_INPUT_PER_MILLION` | USD لكل مليون رمز دخل لـ`gpt-5-nano` | `0.05` |
| `AI_USAGE_GPT5_NANO_OUTPUT_PER_MILLION` | USD لكل مليون رمز خرج لـ`gpt-5-nano` | `0.40` |
| `AI_USAGE_GPT4O_INPUT_PER_MILLION` | USD لكل مليون رمز دخل لـ`gpt-4o` | `2.50` |
| `AI_USAGE_GPT4O_OUTPUT_PER_MILLION` | USD لكل مليون رمز خرج لـ`gpt-4o` | `10.00` |
| `AI_USAGE_GPT4O_MINI_INPUT_PER_MILLION` | USD لكل مليون رمز دخل لـ`gpt-4o-mini` | `0.15` |
| `AI_USAGE_GPT4O_MINI_OUTPUT_PER_MILLION` | USD لكل مليون رمز خرج لـ`gpt-4o-mini` | `0.60` |
| `AI_USAGE_PAYLOAD_RETENTION_DAYS` | مدة حفظ الحمولات التشخيصية | `30` يوماً |

يجب مراجعة الأسعار عند تغيير النموذج أو عقد المزود. يُكتب مبلغ السجل وقت النداء ولا يعاد احتسابه عند تعديل الجدول لاحقاً.

## تحقق حي آمن

على خادم tadgeeg، وبعد نشر الشحنة وتشغيل الهجرات، نفذ الاختبار المقيّد التالي من داخل حاوية الويب. لا يطبع الأمر المفتاح أو نص الرسالة أو الاستجابة؛ ويخرج فقط دليل السجل والرموز والكلفة:

```bash
docker compose -f deployment/docker/docker-compose.yml exec -T web_live \
  python scripts/verify_ai_usage_gateway_live.py
```

يلزم أن تكون الحاوية قد شغلت الهجرات `ai_safety.0002` و`ai_safety.0003`. إذا ظهرت `provider_success: true` مع `usage_recorded: true` و`estimated_cost` موجب، فقد اجتاز التحقق التشغيلي. أما فشل `auth_401` أو `rate_limit` أو `timeout` فيسجل كفشل صريح يجب معالجته، ولا يعد النظام جاهزاً للقياس الحي.

## العرض في CRM

يعرض ملف العميل في CRM، للموظفين الذين يملكون صلاحية البيانات المالية فقط، ملخص الشهر الحالي من `AIUsageRecord`: الطلبات، رموز الدخل والخرج، الكلفة المقدرة، الفشل، ونسبة الفشل، مع تفصيل حسب العملية. لا يعرض CRM `AIUsagePayload` أو محتوى الطلب/الرد أو أي اعتماد.

## نتائج التحقق المحلي

تم تنفيذ نداء واحد مقيد في بيئة اختبار محلية عبر الوكيل المتاح. سجّل النتيجة حالة `success`، و`10` رموز دخل، و`8` رموز خرج، وكلفة موجبة، وتطابقت قيم الاستخدام المحفوظة في الحمولة المنقاة مع صف `AIUsageRecord`. هذا يثبت مسار البوابة والسجل محلياً؛ ولا يستبدل التحقق الحي في خادم tadgeeg لأنه بيئة منفصلة.
