# تقرير دمج `claude` في `main`

**التاريخ:** 2026-08-16

**الفرع المصدر:** `origin/claude` عند `0fd29bc`

**الفرع الهدف قبل الدمج:** `origin/main` عند `3d29066`

**التزام الدمج المحلي:** `5c02ca4`

**النطاق المصرح به:** دمج تاريخ `claude` وتقرير الدمج هذا فقط. لا يتضمن التقرير إصلاحاً جديداً أو تعديل هجرة أو إعادة كتابة لصفوف تدقيق تاريخية.

> **قرار الشحنة:** اجتازت بوابتا ما قبل الدمج وما بعده، ولم يظهر تعارض. الدفع إلى `main` مسموح بموجب تصريح CTO؛ أما النشر إلى الإنتاج فمحجوب بالبند التاسع أدناه.

## 1. التفويض وحدود الشحنة

ورد تصريح CTO مكتوب يذكر صراحة دمج `claude` في `main` ودفع `main` إلى `origin`. بقي العمل ضمن دمج `--no-ff` وتقرير توثيقي. لم يُحل أي تعارض باجتهاد لأن الدمج لم ينتج تعارضاً، ولم تُفتح بنود مسجلة أو شحنات تحسين أثناء هذا المسار.

| القيد | النتيجة |
|---|---|
| الفرع المصدر | `claude` فقط |
| الهدف | `main` فقط |
| أسلوب الدمج | `git merge --no-ff origin/claude` |
| تعديلات شيفرة ضمن مسار الدمج | صفر |
| تعارضات | صفر |
| دفع الإنتاج | غير مصرح به بهذه الشحنة |

## 2. المسح العام قبل الدمج

أعيد القياس بدلاً من نقل رقم تاريخي. كانت شجرة `claude` النظيفة عند `0fd29bc`، و`main` البعيد عند `3d29066` كما يشترط التصريح. وكان `main` سلفاً لـ`claude`، وعدد الالتزامات في المجال `origin/main..origin/claude` هو **51**.

| فحص | النتيجة |
|---|---|
| `git status --short` على شجرة `claude` | نظيفة |
| `origin/claude` | `0fd29bc` |
| `origin/main` | `3d29066` |
| `origin/main` سلف لـ`origin/claude` | نعم |
| التزامات المجال | 51 |

## 3. بوابة `claude` قبل الدمج

أجريت البوابة الكاملة على محتوى `claude` قبل أي عملية دمج. النتيجة الوظيفية خضراء: **4,043 ناجحاً، 4 متخطاة، و18 اختباراً فرعياً ناجحاً**. الفشل الوحيد هو `test_compiled_catalogue_is_not_stale`، وهو اختبار timestamp لكتالوج العربية؛ طابع `django.po` كان أحدث من `django.mo` بفارق أجزاء من الألف من الثانية. هذا هو الفشل البيئي المعروف، وليس فشلاً وظيفياً في الشحنة.

كما أعاد `python manage.py makemigrations --check --dry-run` النتيجة **`No changes detected`**.

## 4. نتيجة الدمج

أنشئ الدمج `5c02ca4` في شجرة معزولة من `origin/main` بالأمر `git merge --no-ff origin/claude`. والدان الالتزام هما `3d29066` و`0fd29bc`، لذلك يبقى تاريخ شحنة `claude` مرئياً ويمكن التراجع عن كامل الدمج بتراجع واحد إن لزم. لم يقع تعارض ولم يتطلب المسار أي تحرير لشيفرة `main`.

## 5. بوابة `main` بعد الدمج

أعيدت بوابة الاختبارات والهجرات بعد الدمج نفسه، لا اعتماداً على نتيجة قبل الدمج. النتيجة مطابقة وظيفياً للبوابة السابقة.

| الفحص بعد الدمج | النتيجة |
|---|---|
| `pytest -q --no-cov` | 4,043 ناجحاً، 4 متخطاة، 18 اختباراً فرعياً ناجحاً |
| فشل pytest | فشل timestamp العربي البيئي المعروف فقط |
| `makemigrations --check --dry-run` | `No changes detected` |
| أخطاء وظيفية جديدة | صفر |

## 6. فحص النشر والتحذيرات المرتبة

شُغّل `python manage.py check --deploy` على `claude` قبل الدمج وعلى `main` بعد الدمج تحت إعداد DEBUG=False محلي مكافئ، ثم رتبت المخرجات وقورنت بعد تطبيع مسارات شجرات العمل. الفرق الخام الأول كان أسماء مسارات `/home/ubuntu/tadgeeg-*` وسطر INFO زمني لتثبيت `quota_gate`؛ كلاهما ليس تحذيراً جديداً. بعد حذف هذين العاملين الشكليين، كانت نتيجة المقارنة: **صفر تحذيرات جديدة**.

> تحذيرات `drf_spectacular` التاريخية بقيت قائمة، لكنها لم تتغير في العدد أو المضمون من `claude` إلى `main`.

## 7. سجل الانحرافات والتصحيحات المنهجية

هذا التقرير يسجل الأخطاء التي صححها القياس بدلاً من إخفائها:

| الانحراف | التصحيح المعتمد |
|---|---|
| خمسة أرقام نُقلت من تقارير سابقة بلا قياس جديد | أُعيد القياس في بوابات ومسوحات الشحنات قبل اعتماد أي رقم |
| وصف «سبع migrations» | الصحيح هجرتان تشغيليتان مرتبطتان بالملء الرجعي: `0017` و`0018` |
| فرضية FI-01 الأولى: `this.uploading` | المصدر المثبت هو تحميل Alpine مكرر في **قالبين**، لا حالة الواجهة وحدها |
| مقارنة تحذيرات `check --deploy` الخام | طُبّعت المسارات واستبعد سطر INFO الزمني؛ المقارنة الفعلية أظهرت صفراً من التحذيرات الجديدة |
| تنظيف بيانات القياس صفاً صفاً | لا يصلح لجداول HashChain؛ قاعدة القياس المحلية تُسقط وتُعاد migrations بعد حفظ الأدلة |

## 8. ما دخل إلى `main`

الدمج ينقل النظام من خمس منظومات حكم ظاهرة إلى **ثلاث** عبر إزالة `AuditEngine` القديم و18 قاعدة مرتبطة به، بإجمالي **2,363 سطراً محذوفاً** في شحنة الحذف. كما ينقل سبعة إصلاحات تشغيلية موجزة:

1. تثبيت مسار الرفع على V1 لمنع انقسام جيل المحرك بين API والرفع.
2. استعادة ملء `audit_document` للصفوف التاريخية عبر الهجرة اللاحقة `0018`.
3. استبعاد الفاتورة ذاتها من كشف التكرار.
4. اشتقاق `subtotal` الصحيح من الإجمالي والضريبة عند وجود القيم اللازمة.
5. إعطاء بيانات المحلل السليمة أسبقية على fallback الذكائي الفاشل.
6. قراءة الفواتير المنظمة: JSON المفرد وXLSX `Field | Value`.
7. منع FI-01: إزالة تحميل Alpine المكرر بحيث تنتج ضغطة الرفع صفاً واحداً.

وتشمل الشحنة أيضاً ترقية Django من 4.2 خارج الدعم إلى **Django 5.2 LTS**، وتحقق قارئ الفواتير حياً للأنواع JSON وXLSX وPDF وPNG.

## 9. النشر إلى الإنتاج محجوب

الدفع إلى GitHub ليس نشراً. يمنع النشر إلى الإنتاج إلى أن ينفذ المشغل البنود الآتية كما هي:

1. تنفيذ `migrate` على بيئة dev أولاً؛ فالهجرتان `0017` و`0018` تعالجان بيئات لم تطبق الملء الرجعي، وpytest لا يكشف هذه الحالة لأنه يبني قاعدة اختبار مهاجرة.
2. مراقبة dev لمدة يومين بعد الهجرة.
3. إشعار المدققين بأن أرقام اللوحات قد تتغير، لأن مستندات سابقة أصبحت تدقق، وCTL-006 صار يقرأ دليله، والقارئ يستخرج مبالغ حقيقية بدلاً من الأصفار.
4. بناء والتحقق الفعلي من WhiteNoise/static manifest على dev.
5. فحص متصفح على dev بعد النشر.

## 10. البنود المفتوحة وإغلاق الخطة

الخطة التطويرية الحالية مغلقة بعد هذا الدمج، لكن البنود التالية تبقى مسجلة ولا يعالجها هذا الالتزام: **AuditRun البيئي، خمس قواعد تنجح على افتراض، حقن 15.0/SAR، FI-02، وFI-03**. كما أن بيئة اختبار قابلة لإعادة البناء مطلوبة لاحقاً لفتح قياس التحمل وملف القفل والمرجع الموسع.
