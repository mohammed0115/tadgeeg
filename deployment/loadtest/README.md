# اختبار الحمل

الأداء في التقييم الشامل مسجَّل **«تعذّر التحقق»** — ولا يزال. هذا هو الوضع
الصادق: رقم تحمُّل لم يُنتجه أحد ليس ادّعاء سعة.

```bash
pip install locust

export LOADTEST_EMAIL=loadtest@yourorg.sa
export LOADTEST_PASSWORD='…'

locust -f deployment/loadtest/audit_pipeline.py --host https://dev.tadgeeg.com
```

ثم افتح `http://localhost:8089` واختر عدد المستخدمين.

## ⚠️ على `dev` لا `live`

السكربت **يرفض** التشغيل على الإنتاج. السبب ليس الحذر المجرّد: التشغيل يُحدث
كتابات حقيقية، **ويستهلك حصّة الفواتير** للمستأجر — وحين تنفد الحصّة تبدأ
القياسات في قياس مسار الـ402 لا الإنتاجية.

## ما تراقبه، بالترتيب

| # | المؤشّر | ماذا يعني |
|---|---|---|
| ١ | **p95 على `/analytics/live/`** | يعمل على كل تبويب مفتوح كل ١٠ث ومخزَّن ٥ث. إن ارتفع مع التزامن فالتخزين لا يعمل، وكل تبويب يضرب MySQL |
| ٢ | **أي 402** | نفدت الحصّة — كل رقم بعد هذه النقطة بلا معنى |
| ٣ | **أي 500** | بثلاثة عمّال gunicorn ومهلة ٣٠ث، أول ما ينهار هو تصيير تقرير يحجز عاملًا |
| ٤ | **خطأ 3024 في سجلّ MySQL** | الحارس **يعمل** لا يفشل — استعلام تجاوز ٣٠ث فأُجهض |

## لماذا نوعان من المستخدمين

`Auditor` يتصفّح ويفكّر بين النقرات. `Poller` تبويب متروك مفتوحًا: لا يتنقّل،
ولا يفكّر، وفي مكتب حقيقي عددهم أكبر من عدد المدقّقين النشطين. دمجهما في نوع
واحد **يقلّل من حمل الاستطلاع** — وهو الحمل الذي لا يتوقّف.

## الأوزان

مبنيّة على ما يعمل صباحًا مزدحمًا لا على ما يثير الفضول:

```

10  /dashboard/          ← يفتحه الجميع أول اليوم
 8  /invoices/           ← سطح العمل
 4  /vendors/
 3  /reports/
 1  تصيير PDF            ← الأغلى: ٥-١٥ث ويحجز عاملًا
```
