# JSON مفرد في رفع الفواتير

## المشكلة

كان `iter_structured_records()` يقبل JSON قائمياً فقط. عند رفع كائن فاتورة واحد، يعيد صفوفاً فارغة، فيسقط الطلب إلى مسار الملف العام ثم AI/fallback. هذا هو المسار الذي كان يسمح لشظايا مثل `oice` بالوصول إلى بيانات الفاتورة.

## التغيير

يعامل المحول الآن كائن JSON في الجذر كسجل منظم واحد برقم صف `1`. يبقى JSON القائمي كما هو، ويبقى الإدخال غير القائمي خارج نطاق المحول. القيم الرقمية تمر عبر `normalize_row` كنصوص قابلة للتطبيع اللاحق، مثل CSV وXLSX.

## الحراسة

شُغل:

```text
pytest -q tests/test_structured_invoice_rows.py --no-cov
2 passed
```

الحارس الجديد يمرر كائن JSON حقيقياً في `BytesIO` ويثبت أن الرقم والمورد والمبالغ تصل كسجل واحد منظم. لا يستخدم Mock.

## خارج النطاق

لا تعالج هذه الشحنة JSON القائمي (كان مدعوماً)، ولا XLSX key/value ولا regex PDF ولا جاهزية Tesseract. هذه محولات مستقلة وتبقى مقاسة في تقرير أسبقية الدمج.
