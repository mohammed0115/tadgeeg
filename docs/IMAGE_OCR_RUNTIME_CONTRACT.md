# عقد تشغيل OCR لصور الفواتير

## المشكلة

كان مسار صورة الفاتورة في بيئة القياس ينتهي بنجاح فارغ حين لا يكون `tesseract` مثبتاً. أنتج ذلك مستنداً بلا نص وبمبالغ صفرية بدلاً من إشارة تشغيلية واضحة.

## القياس

بعد تثبيت الاعتمادات التي يعلنها Dockerfile (`tesseract-ocr` واللغتان `eng` و`ara`)، شغلت عينة PNG نفسها عبر `DocumentEngine`.

| المؤشر | النتيجة |
|---|---|
| محرك الإدخال | `ocr_fallback` |
| ثقة OCR | 95.08 |
| رقم الفاتورة | `XFMT-2026-001` |
| المورد | `Cross Format Supplier Ltd` |
| subtotal / VAT / الإجمالي | 1000 / 150 / 1150 |

## الحارس

يضيف الاختبار حارساً حقيقياً بلا skip أو Mock. ينشئ PNG فاتورة ويشغل `DocumentEngine` ثم fallback الفعلي. غياب `tesseract` يجعل الحارس يفشل برسالة تشغيلية صريحة؛ وهذا عقد مقصود لأن المنصة تقبل صور فواتير.

```text
pytest -q tests/test_image_ocr_runtime_contract.py --no-cov
1 passed
```

CI الحالي يثبت `tesseract-ocr`، وDockerfile يثبت حزم OCR العربية والإنجليزية؛ لم تُعدل شحنة الصورة ملف CI.

## بوابة الشحنة

أعيد تشغيل البوابة الكاملة بعد إضافة الحارس:

```text
1 failed, 4039 passed, 4 skipped, 18 subtests passed in 296.80s
```

الفشل الوحيد هو مقارنة `mtime` لكتالوج العربية بفارق 0.004 ثانية؛ وهو العارض البيئي المعروف ولا يتعلق بمسار OCR للصورة.
